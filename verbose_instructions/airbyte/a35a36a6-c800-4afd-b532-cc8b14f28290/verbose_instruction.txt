1) Switch to the terminal window that has access to the Airbyte deployment and the Octavia CLI binaries.  
2) Run the Octavia project bootstrap command:  
```bash
octavia init
```  
(The command scaffolds the ./sources, ./destinations, and ./connections folders – we will fill them in next.)

3) Generate a Postgres SOURCE resource skeleton:  
```bash
octavia generate source decd338e-5647-4c0b-adf4-da0e75f5a750 postgres
```  
Octavia creates ./sources/postgres/configuration.yaml and opens a summary path in the console.

4) Open the generated file for editing:  
```bash
nano sources/postgres/configuration.yaml
```  

5) Replace the entire contents with the exact configuration taken from the Desktop → config.json (values copied verbatim):  
```yaml
resource_name: "postgres"
definition_type: source
definition_id: decd338e-5647-4c0b-adf4-da0e75f5a750
definition_image: airbyte/source-postgres
definition_version: 3.3.18

configuration:
  host: "localhost"
  port: 2000
  schemas: ["public"]
  database: "postgres"
  password: "password"
  ssl_mode:
    mode: "disable"
  username: "postgres"
  tunnel_method:
    tunnel_method: "NO_TUNNEL"
  jdbc_url_params: ""
  replication_method:
    method: "Standard"
```  
6) Press Ctrl + O, then Enter to write the file, and Ctrl + X to exit nano.

7) Apply the SOURCE to Airbyte:  
```bash
octavia apply
```  
Verify the terminal prints:  
🎉 - Successfully created postgres on your Airbyte instance!

8) Generate a Postgres DESTINATION skeleton:  
```bash
octavia generate destination 25c5221d-dce2-4163-ade9-739ef790f503 postgres
```  

9) Open the destination YAML for editing:  
```bash
nano destinations/postgres/configuration.yaml
```  

10) Overwrite the content so it matches the desktop config file:  
```yaml
resource_name: "postgres"
definition_type: destination
definition_id: 25c5221d-dce2-4163-ade9-739ef790f503
definition_image: airbyte/destination-postgres
definition_version: 2.0.4

configuration:
  ssl: false
  host: "localhost"
  port: 3000
  schema: "public"
  database: "postgres"
  password: "password"
  ssl_mode:
    mode: "disable"
  username: "postgres"
  tunnel_method:
    tunnel_method: "NO_TUNNEL"
  jdbc_url_params: ""
  raw_data_schema: ""
  disable_type_dedupe: false
```  

11) Save (Ctrl + O → Enter) and exit nano (Ctrl + X).

12) Push the DESTINATION to Airbyte:  
```bash
octavia apply
```  
Confirm the success message mirrors step 7.

13) Create the CONNECTION definition that stitches the two resources:  
```bash
octavia generate connection \
  --source sources/postgres/configuration.yaml \
  --destination destinations/postgres/configuration.yaml \
  postgres-to-postgres
```  
Octavia generates ./connections/postgres_to_postgres/configuration.yaml.

14) Open the connection file:  
```bash
nano connections/postgres_to_postgres/configuration.yaml
```  

15) Paste the full configuration below, adjusting only stream names if your source differs; everything else comes directly from the desktop file:  
```yaml
definition_type: connection
resource_name: "postgres-to-postgres"
source_configuration_path: sources/postgres/configuration.yaml
destination_configuration_path: destinations/postgres/configuration.yaml

configuration:
  status: active
  skip_reset: false
  namespace_definition: source
  namespace_format: "${SOURCE_NAMESPACE}"
  prefix: ""
  schedule_type: manual
  sync_catalog:
    streams:
      - config:
          alias_name: basic_file
          cursor_field: []
          destination_sync_mode: overwrite
          primary_key:
            - - id
          selected: true
          suggested: true
          sync_mode: full_refresh
        stream:
          default_cursor_field: []
          json_schema:
            properties:
              id:
                airbyte_type: integer
                type: number
              name:
                type: string
            type: object
          name: basic_file
          namespace: public
          source_defined_primary_key:
            - - id
          supported_sync_modes:
            - full_refresh
            - incremental
```  

16) Save and exit nano.

17) Apply the CONNECTION:  
```bash
octavia apply
```  
Look for:  
🎉 - Successfully created postgres-to-postgres on your Airbyte instance!

18) Switch to the Airbyte UI (browser tab) → Connections page; verify that a connection named “postgres-to-postgres” appears with status “Active”.

19) Click the connection row, then click “Sync now” in the top-right to trigger the first replication run.

20) Wait until the status changes to “Succeeded”. Congratulations—data is now flowing from Postgres → Postgres using Octavia-managed configuration!
