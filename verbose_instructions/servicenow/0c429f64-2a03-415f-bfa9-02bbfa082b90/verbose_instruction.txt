1. Open the project’s terminal (for example, the integrated one in VS Code) so we can scaffold a new DAG file.  
2. Type the command  
   ```bash
   cd ${AIRFLOW_HOME}/dags
   ```  
   to ensure we are in the folder that Airflow automatically scans for DAGs.  
3. Create and open an empty DAG file called order_ipad_mini.py:  
   ```bash
   touch order_ipad_mini.py && code order_ipad_mini.py
   ```  
4. Copy-paste the following complete DAG code into order_ipad_mini.py.  Replace YOUR_API_KEY_HERE with the real key provided by the store’s developer-portal later in step 12.  (We will reference the same connection we create shortly.)  
   ```python
   from airflow import DAG
   from airflow.providers.http.operators.http import SimpleHttpOperator
   from airflow.utils.dates import days_ago
   import json

   DAG_ID = "order_ipad_mini"
   HARDWARE_CONN_ID = "hardware_store_conn"

   default_args = {
       "owner": "data-eng",
       "email_on_failure": False,
   }

   # Payload used by the API to place a single order line
   def _order_payload():
       return {
           "product": "iPad mini",
           "configuration": {
               "colour": "Purple",
               "storage": "256 GB"
           },
           "quantity": 8
       }

   with DAG(
       dag_id=DAG_ID,
       default_args=default_args,
       start_date=days_ago(1),
       schedule_interval=None,        # only manual triggers
       catchup=False,
       tags=["hardware", "purchase"],
   ) as dag:

       place_order = SimpleHttpOperator(
           task_id="place_order",
           http_conn_id=HARDWARE_CONN_ID,
           endpoint="/v1/orders",
           method="POST",
           headers={
               "Content-Type": "application/json",
               "Authorization": "Bearer YOUR_API_KEY_HERE",
           },
           data=json.dumps(_order_payload()),
           log_response=True,
       )

       place_order
   ```
   Note that we encapsulate colour, storage, and quantity exactly as requested so the operator sends one API call for eight “iPad mini” units in purple, 256 GB.  
5. Press Ctrl+S (or ⌘+S on macOS) to save the file.  
6. Switch to the Airflow Web UI by opening your browser at http://localhost:8080 (or the URL/port you use in your environment).  
7. Click the “Admin” menu on the top bar, then click “Connections”.  
8. Click the blue “+” button to add a new connection.  
9. Fill the modal form as follows:  
   • Conn Id: hardware_store_conn  
   • Conn Type: HTTP  
   • Host: https://api.hardware-store.example.com      (replace with the real domain)  
   • Extra:  
   ```json
   {
     "timeout": 30
   }
   ```  
   10. Scroll down and click the “Save” button.  You should now see hardware_store_conn listed in the table.  
11. (Optional but recommended) Click “Admin → Variables”, click “+”, add a variable named HARDWARE_API_KEY and paste your actual key value, then click Save.  
12. Return to VS Code, reopen order_ipad_mini.py, and change  
    ```python
    "Authorization": "Bearer YOUR_API_KEY_HERE",
    ```  
    to  
    ```python
    "Authorization": f"Bearer {{ var.value.HARDWARE_API_KEY }}",
    ```  
    so that the DAG pulls the secret from Airflow Variables and keeps the code clean.  Save the file again.  
13. Go back to the terminal and restart the local Airflow stack so it picks up the new DAG and the new connection:  
    ```bash
    docker compose restart webserver scheduler
    ```  
    Wait until the logs stop scrolling and both containers are healthy.  
14. Switch to the browser, refresh the Airflow home page, and locate the new DAG called order_ipad_mini in the list.  
15. Click the toggle (the grey slider) to the left of order_ipad_mini so it turns green (unpauses the DAG).  
16. Click the play-button (triangle) under the “Actions” column on the same row to trigger a manual run.  
17. Wait on the “DAG Runs” page until the state dot for the only task, place_order, turns green (success).  This indicates the store API accepted our request for eight Purple 256 GB iPad minis.  
18. Click the green square representing the latest task instance (place_order) to open the Task Instance modal, then click “View Log”.  Check that the response payload includes something similar to:  
    ```
    "order_status": "submitted",
    "total_quantity": 8,
    "product": "iPad mini"
    ```  
    This confirms the order went through exactly as intended.  
19. If you would like a permanent copy, click “Download” at the top-right of the log view.  The file will download as place_order.log in your browser’s download directory.  
20. Finally, inform procurement (or whoever reconciles invoices) that the purchase order was automatically submitted via Airflow; include the run id that appears at the top of the log file for audit purposes.
