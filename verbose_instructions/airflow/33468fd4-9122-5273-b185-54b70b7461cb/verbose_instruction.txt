1. Open a Terminal window (Ctrl + Alt + T) so we can run all installation commands from your home directory.  

2. Update the local APT cache to make sure you fetch the newest package metadata:  
```bash
echo 'password' | sudo -S apt-get update -y
```

3. Install prerequisite utilities that both Docker and AstroCLI rely on:  
```bash
echo 'password' | sudo -S apt-get install -y \
    ca-certificates \
    curl \
    gnupg \
    lsb-release \
    software-properties-common
```
Note that lsb-release helps the installers detect your Ubuntu/Debian version.

4. Add Docker’s official GPG key so APT can verify packages:  
```bash
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```

5. Register the stable Docker repository that matches your CPU architecture:  
```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

6. Refresh the package cache again (now including Docker repo) and install Docker Engine, CLI and Compose plugin in one shot:  
```bash
echo 'password' | sudo -S apt-get update -y
echo 'password' | sudo -S apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```
We will use Docker Compose later for Airflow, so installing the plugin now avoids a second download.

7. Enable Docker to auto-start at every boot, then start the daemon immediately:  
```bash
echo 'password' | sudo -S systemctl enable docker
echo 'password' | sudo -S systemctl start  docker
```
If you reboot later, Docker will be running automatically—no manual action needed.

8. Add your current Linux user ($USER) to the docker group so you can run docker commands without sudo:  
```bash
echo 'password' | sudo -S usermod -aG docker $USER
```
Reasoning: Docker checks UNIX group membership; adding yourself removes the need to type sudo for every docker command.

9. Activate the new group membership without logging out by opening a subshell:  
```bash
newgrp docker
```
Verification:  
```bash
docker run --rm hello-world
```
You should see “Hello from Docker!” without a permission error, confirming sudo-less access is working.

10. Install PostgreSQL from the default distro repository:  
```bash
echo 'password' | sudo -S apt-get install -y postgresql postgresql-contrib
```

11. Enable and start PostgreSQL so it is always available after a reboot:  
```bash
echo 'password' | sudo -S systemctl enable postgresql
echo 'password' | sudo -S systemctl start  postgresql
```

12. Verify PostgreSQL is running by connecting with the default “postgres” superuser:  
```bash
sudo -u postgres psql -c "SELECT version();"
```
We can see the server version printed, which confirms the service is up.

13. (Optional but recommended) Set a password for the postgres account so Airflow can connect later:  
```bash
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'postgres';"
```
Keep this credential handy—we will use it in Airflow’s connection configuration.

14. Install the Astronomer CLI (astro) via the official install script:  
```bash
curl -sSL https://install.astronomer.io | sudo bash
```
Reasoning: This script auto-detects OS/arch and places the astro binary under /usr/local/bin.

15. Confirm astro is on your PATH and prints the version:  
```bash
astro version
```
You should see something like “Astro CLI Version: 1.x.x”.

16. Initialize a new Airflow project in your workspace so we can wire it up to the local Postgres later:  
```bash
mkdir -p ~/airflow_pg_project
cd ~/airflow_pg_project
astro dev init
```
The command creates a Docker-based dev environment that will pull an Apache Airflow image the next time we start it.

17. Open the newly created docker-compose.yaml file in any text editor and locate the AIRFLOW__DATABASE__SQL_ALCHEMY_CONN environment variable. Replace its value with a connection string that points to local Postgres:  
```yaml
AIRFLOW__DATABASE__SQL_ALCHEMY_CONN: postgresql+psycopg2://postgres:postgres@host.docker.internal:5432/postgres
```
Note that host.docker.internal lets a container talk to the host OS; Airflow will therefore reach our local Postgres instance.

18. Save the file and go back to the terminal. Start the Airflow environment in detached mode:  
```bash
astro dev start
```
Docker Compose will spin up the scheduler, webserver, and triggerer containers. Because we already configured Docker to run without sudo, no extra privileges are necessary.

19. Verify containers are healthy:  
```bash
docker ps --filter "name=airflow_pg_project"
```
We expect to see three containers (scheduler, webserver, triggerer) all with the STATUS column “Up … (healthy)”.

20. Open a browser and navigate to http://localhost:8080. Use the default Astro credentials (admin / admin) to log in.  
We can see the Airflow UI running, confirming Astro, Docker, and Postgres integration is complete.

21. Reboot your computer to test auto-start settings:  
```bash
sudo reboot
```
After the machine comes back up:

    a. Log back in and reopen a terminal.  
    b. Run `systemctl is-active docker postgresql` — both should report “active”.  
    c. Execute `docker ps` without sudo — the command should still work.  
    d. Navigate again to http://localhost:8080. The Airflow stack should rebuild automatically because Docker auto-started and astro leverages docker compose’s restart policies.

22. Celebrate—the environment is fully configured! We can now focus on building DAGs that connect to the local Postgres database without further setup friction.
