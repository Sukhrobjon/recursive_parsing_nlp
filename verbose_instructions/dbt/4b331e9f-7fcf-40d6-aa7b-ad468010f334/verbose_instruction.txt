1) Open VS Code and load the dbt project folder (e.g., ~/projects/jaffle_shop) so we can inspect the snapshot calling the missing source.  

2) Expand the snapshots/ directory in the Explorer panel and click the file orders_snapshot.sql.  

3) Scan the top portion of the file and identify the reference that is failing; you will see something like:  
```sql
from {{ source('raw_jaffle_shop', 'orders') }}
```
We can see the source called raw_jaffle_shop.orders is referenced but never declared.  

4) Switch to the Explorer panel, right-click the models/ folder, and choose “New File”.  

5) Type sources.yml and press Enter so the file is created at models/sources.yml.  

6) Click into sources.yml and type the following YAML block to declare the missing source (adjust database / schema names if your warehouse differs):

```yaml
version: 2

sources:
  - name: raw_jaffle_shop          # must match the first argument in source()
    database: raw                 # warehouse database that actually stores the table
    schema: jaffle_shop           # physical schema where the raw table lives
    tables:
      - name: orders              # must match the second argument in source()
        description: "Raw orders table landed by ingestion pipeline"
        loaded_at_field: _loaded_at   # set to your warehouse load timestamp column
        freshness:
          warn_after: {count: 24, period: hour}
          error_after: {count: 48, period: hour}
```

7) Press Ctrl+S (Cmd+S on macOS) to save sources.yml.  

8) Switch to the integrated Terminal in VS Code (or open a new terminal window) and make sure you are inside the project root:  
```bash
cd ~/projects/jaffle_shop
```

9) Run a quick compile to confirm the YAML is syntactically valid:  
```bash
dbt compile
```
You should see the message “Compilation finished” with no source-related errors.

10) Execute a full run of models so everything depending on the new source is materialised:  
```bash
dbt run
```
Verify the terminal shows green “OK” statuses for each model.

11) Now trigger the snapshots, including orders_snapshot, which previously failed:  
```bash
dbt snapshot
```
You should see “OK” for orders_snapshot and zero failures.

12) Run the built-in diagnostic to be doubly sure all sources/models/snapshots are healthy:  
```bash
dbt test --store-failures
```
Check that every test passes; any issues will be displayed in red.

13) Commit the change so teammates also have the source declaration:  
```bash
git add models/sources.yml snapshots/orders_snapshot.sql
git commit -m "Add raw_jaffle_shop.orders source and fix orders_snapshot"
git push
```

14) (Optional) If you are in a CI/CD environment, verify the pipeline now completes without the previous “undeclared source” error.
